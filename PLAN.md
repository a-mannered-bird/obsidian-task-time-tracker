# Plan

Roadmap and todo lists for the Task Time Tracker plugin. Decisions recorded here were taken on 2026-08-16 (phases 0–4) and 2026-08-30 (phases 5–8); update the checkboxes as work lands.

## Decisions

- The plugin owns the tracking commands (port of the `taskSwitcher.js` QuickAdd script), wake/bed time, and end-of-day cleanup. Task-dictionary sync (Various Complements) and per-task quick actions come later.
- Commands: one Obsidian command per flag combination actually used (hotkey-friendly), all thin wrappers over a single `toggleTasks(options)` core. A button panel on top of the same core is a later phase.
- Task picker: Obsidian `FuzzySuggestModal`; minutes prompts: small `Modal`. No dependency on QuickAdd.
- Tag → emoji / text-style mapping is one setting, replacing the hardcoded lists in `tracker.ts` and the emoji flags in the script.
- Target file: the active file if it is a daily note, otherwise today's daily note. Daily-note detection = plugin settings `dailyNotesFolder` (default: vault root, like the core Daily Notes plugin) + `dateFormat` (default `YYYY-MM-DD`). Inheriting from the core Daily Notes plugin is a follow-up.
- Wake/bed time via `app.fileManager.processFrontMatter`, property names configurable, wake offset default -3 min.
- "Getting up" macro is split: "Set wake time" is a pure command; the "also toggle task X" part becomes a per-task quick action later.
- "Complete journal entry": close still-open clocks (same timestamp as bed time), tick clocked tasks, remove unclocked ones, with a confirm modal listing what will be deleted.
- One shared data layer (`DailyLogStore.loadRange → DailyLog[]`, cached, invalidated on vault events) and one line-based parser used for both reading stats and rewriting the note. Prerequisite for the flexible views.
- Flexible views: `task-stats` code block first (saved view = code block in a note), sidebar controls later, both on the same Svelte components.
- Renamed 2026-11-13: wake/bed time became start/end of day, so the day window fits any use (waking hours, a work day). Frontmatter `day_start` / `day_end`, commands `set-day-start` / `set-day-end`, quick-action flags `setDayStart` / `setDayEnd`, and the "sleep" statistic became "off time". No migration: the only user renamed the properties in their notes by hand. Wake/bed wording below predates this.
- Day boundaries (2026-11-13): the start of day is never after the end of day, and the end of day never before the start nor the note's clocks (a closed clock's end, a running one's start, since End day closes it). Typed in a prompt, an end time of day before that floor means the next day, while minutes ago before it are refused; a start after the end is refused. In the timeline the Start and End labels are handles: dragged, the line snaps like a clock edge and stops at those bounds; clicked, they open the same prompt.
- First task asks for the start of day (2026-11-18): the first clock started in a note without a `day_start` opens a "Start of day" prompt ("It's the first task of the day! But when did your day actually start?") on the task's start, minutes counted back from it, never after it. The answer goes into the same write as the clock; dismissing it cancels the whole action, like every tracking prompt. Replaces the silent "start of day = first clock" below for tracking writes.
- Automatic day boundaries (2026-11-17): the first clock started in a note without one sets `day_start` to its start, and stopping the last clock still running from an earlier day (the overnight card) sets that note's `day_end` to its last clock's end, earlier or later than a recorded one (changed 2026-11-17: it follows the stop exactly). Both go into the same write as the clock (a frontmatter line edited in the note text, `core/frontmatter.ts`), so one Undo restores both and Change moves both (a start of day sitting on the first clock follows it). Typed and dragged start/end of day use the same text edit, so their notices also offer Change and Undo. Notices say "Start of day set to 07:05." instead of the raw property; the line under the time fields names another day by its date ("Friday, November 13 at 00:30"). On layout ready both properties get the "Date & time" type unless the user chose one (private `metadataTypeManager`, verified on 1.15.1).
- Ranges: today, this week (Monday start), last 7 days, this month, last month, last 3 months, this year, last year, all, custom `from..to`.
- Group by: task name, tag. Metrics: total, per-day average (option to skip empty days), per-day breakdown as charts, time-of-day (sleep, unlogged, average wake and bed time). Loading a range also loads the day before `range.start` (previous bed time).
- Charts: hand-rolled SVG in Svelte, themed with Obsidian CSS variables. No chart library for now.
- Tests: Vitest on pure TS (parser, interval math, aggregation, range resolution). No component tests initially.
- Keep `main.js` out of git (already ignored); build in CI at release time.

## Decisions (2026-08-30): vault-wide picker + task management

- Task identity stays **name-only**; tags remain per-line decoration and the markdown daily notes remain the single source of truth. No canonical task registry. Only data that cannot live in markdown goes to plugin settings: `name → color`, `name → hidden-from-picker`. Rename/merge must migrate these name-keyed entries (and `quickActions[].taskName`, `unassignedTaskName`).
- `VaultTaskIndex` on top of `DailyLogStore`: per-name aggregates (occurrence count, last-used date, most-recent tags, total minutes, occurrence locations). Built lazily on first use (picker or panel), updated incrementally via store events. Design target: 10k+ daily notes; while the first scan runs, the picker shows a loading row.
- Picker keeps stock `FuzzySuggestModal`: `getItems()` = note tasks (current sort) + full deduped vault index (note entry wins); `limit` = note-task count + 50 caps rendering only — typing fuzzy-searches the whole index. Revised 2026-09-05: while typing, the matching note tasks come first (fuzzy order), then the matching vault tasks — today's tasks are what the user most likely means. Vault entries default-ordered by usage count desc, labeled with most-recent tags for the emoji.
- Picking a vault task not in the note inserts its line (after the last task line, end of file if none; unticked; most-recent tags) into the shared `TaskNote` inside the `Prompts.pickTask` wrapper — the toggle engine stays untouched. Scope: main toggle/switch picker and migrate/interruption target; not set-duration (running tasks only). `Prompts.pickTask` grows an option to include/exclude the vault section.
- Create-from-text row: shown last and visually distinct whenever the trimmed, tag-stripped query doesn't case-insensitively equal an existing name; tags parsed from the typed text with the parser's `TAG` regex; no tags typed = bare line. Exact match on a hidden task resurfaces it instead of offering a duplicate. Identity/toggling stays case-sensitive; only the create-offer check is case-insensitive.
- Settings ship one picker knob only: a global "include vault tasks" toggle. Per-task hiding lives in the management panel; no recency-window setting. Revised 2026-11-13: the toggle is gone, every picker but set-duration always offers the vault tasks and the create row. Suggesting other notes' tasks is a core feature to encourage, and with the vault off the create row could only check the note's names for twins. Per-task hiding remains the way to quiet the list. The tracker's bar and the modal build their rows with the same `taskSuggestions` (core/taskPicker), so both order and filter alike.
- Task management UI is a dedicated large `Modal` (Svelte content), not a settings-embedded table. Entry points: command, button in a small settings section, button in the tracker tab. Table columns: color swatch (inline picker), name + most-recent tag chips, note count, total time, last used, warning icons, overflow menu (rename / retag / hide / delete). Sortable headers (default: count desc), text filter, warnings-only toggle, render capped at ~200 rows ("showing X of Y").
- Bulk rewrites use `vault.process` per file, only writing changed files, sequential with progress notice and end summary (failures reported, re-run is the recovery). Confirmation previews show index-derived blast radius; type-the-name ritual for delete and merge only; warning text mentions core File Recovery as the escape hatch — no custom undo.
- Rename and merge share one consolidation engine (rename = 1-source merge). Within a note, colliding lines consolidate: the target-name line survives (keeps position/tags), other lines' clocks move under it, ticked = OR. Per-line tags are kept — resulting tag drift is surfaced by the drift flag and fixed via retag. Clock union via `mergeIntervals` semantics (overlapping _and_ touching merge; zero-length dropped but counted in the preview); if any clock in a group is running, the merged clock keeps the earliest start and stays running.
- Merge UI: checkbox per row + "Merge N tasks…" button (≥2), survivor name chosen in the confirm modal (default: most used).
- Bulk selection (decided 2026-09-01): the header checkbox selects every matching task (the filtered set, not just the rendered cap), shift-click ticks the range since the last plain click in table order, and a selection bar offers merge, change tags, color, hide/show and delete over the selection. Deleting several tasks types the count instead of a name.
- Retag UI (decided 2026-09-01): a chip editor over the union of the task's tags, each chip showing its coverage (`7/12`) when not on every line. Apply means "every line gets exactly these tags" — the normalization that settles tag drift — in one confirmation and one run; disabled when no line would change.
- Sixth issue flag (decided 2026-09-05): a clock lying wholly before the note's wake time or wholly after its bed time is "outside the day" — by the plugin's own day definition it belongs to another note, or the times are wrong; jump-to-line is the only fix. A boundary that is not recorded is not checked (no calendar-day fallback), touching a boundary counts as inside, straddling clocks are left alone.
- Issue flags, computed on panel open from the index, thresholds fixed in v1: (1) name similarity — Damerau-Levenshtein on case-folded, whitespace-collapsed names, distance ≤ 1 under 6 chars else ≤ 2, length-diff ≤ 2 prefilter; similarity warning offers "merge these two". (2) duration outlier — session ≥ 16h always, or > 5× the task's median with ≥ 5 sessions; click jumps to the note line. (3) tag drift across occurrences. (4) same-task overlapping clocks (cross-task overlap is legitimate), with a one-click consolidation fix. (5) stale running clock in a non-today note.
- Colors: panel picker offers the 8 theme `--color-*` swatches plus free hex; the CSS string is stored, overriding `seriesColor` wherever a chart key is a task name. Uncolored tasks keep the rank cycle; collisions accepted in v1. Tag colors deferred (future `color` field on tag mappings — see Later).
- Plugin CSS is static (decided 2026-09-04): `src/styles.css` is imported by `main.ts` and bundled with the Svelte component styles (`css: 'external'`) into the generated, gitignored `styles.css` — what Obsidian's guidelines ask for, and the only CSS the trace player can replay reliably (runtime-injected styles were captured inconsistently).
- E2E debugging (decided 2026-09-04): `@wdio/devtools-service` behind `wdio.debug.conf.mts` — `npm run test:e2e:debug` opens the live DevTools dashboard during the run, `npm run test:e2e:trace` writes `test-results/trace-*.zip` and `npm run test:e2e:trace:open` replays the latest one step by step (DOM time travel, per-command screenshots). `browser.debug()` remains the ad-hoc breakpoint. The normal `test:e2e` stays lean.
- End-to-end tests (decided 2026-08-31): adopt `wdio-obsidian-service` starting with phase 7 — the bulk operations are the first features that can corrupt notes, so each one gets an E2E test running it against a fixture vault and diffing the resulting markdown. Coverage then grows with each phase; earlier features (picker, panel) get E2E tests opportunistically, not retroactively as a blocker.

## Decisions (2026-11-10): notes changing underneath the commands

- **Commands act on what the editor shows.** An open editor saves two seconds after the last change, so a command reading the file right after an edit or an undo saw the previous state, and its write discarded the edit. Tracking commands, tick/untick and Complete journal now save the note's editors first, but only when the user edited after the file's mtime: an editor can also differ from the file because Obsidian has not refreshed it yet after an outside write, and saving that one would overwrite the write. User edits are logged by a CodeMirror update listener (`commands/userEdits.ts`); Obsidian's own reload carries the user event `set` and is excluded (observed on 1.15, undocumented).
- **Tracking writes are compare-and-swap with redo** (`core/trackingRun.ts`). The user can sit in a picker while a sync rewrites the note; the write only lands if the note still holds what was read, otherwise the steps are redone on the new content with the recorded prompt answers, without prompting again. Redo gives up with a notice (nothing written) when the answers no longer apply, in particular when the picked task was started or stopped elsewhere meanwhile, since toggling would then do the opposite of what was chosen.
  - _Amended 2026-11-12: the pickers follow the note live._ While a picker is open, every change of its note (daily log change event, re-read) recomputes the offered tasks through the engine's own filter (`PickTaskRequest.choices`), so a task started elsewhere shows ⏳ and moves up; the highlighted row stays on the same task (through `SuggestModal`'s undocumented `chooser`, guarded, falling back to the first row). A pick is a `TaskChoice` (name, tags, running state as shown), resolved against the note by the engine. When the note changed while a prompt was open, the run starts over on the new content with the answers so far and asks only the prompts not answered yet, instead of redoing on a pick made from a stale list. Notices are held back until the run ends, so only those of the run that counted are shown.
- **Lost clocks are not detected (removed 2026-11-18).** Too many false positives on syncs: the sticky Restore/Dismiss notice described below fired on ordinary sync traffic. The watch, its notice and the acknowledgements writers made to it are gone; bring it back from git history if clocks turn out to vanish in practice. What it did: The plugin cannot see the remote state, so a toggle on an outdated note is reconciled by the sync tool afterwards. Every daily note change is compared with the note's previously cached tasks: a clock whose time the same task no longer covers is lost (merged or closed clocks are not), unless the plugin wrote the change itself (writers acknowledge their content) or the user had an unsaved editor change. A sticky notice lists them with Restore/Dismiss; restoring re-adds the clocks and unions them (same engine as merge), so it is idempotent. Pending losses are kept per note until they come back, are restored or dismissed. Nothing is persisted: the detection only covers notes the plugin has loaded or written in this session.

## Decisions (2026-11-13): clock lines stay in time order

- **Every clock edit re-sorts the edited task's clock lines by start** (`chronologicalClockLines` in `core/note.ts`, applied by the `TaskNote` clock edits: retime, start, add, insert, stop, move last clock). One place covers the tracker tab (change start, set stop, set duration, migrate), the timeline (drag, keys, draw, Undo), the hand-off Change, the toggle engine, End day and lost-clock restores; consolidation already writes its union oldest first. Only the task an edit touched is sorted, other tasks stay as the user wrote them, and nothing is rewritten when the order is already right.
- A running clock is placed by its start like any other. It normally started last, so it stays at the bottom, and the last line stays the latest clock, which migrating the last clock relies on. Clocks starting at the same time keep their order.

## Decisions (2026-11-11): timeline tab

A day-calendar view of the note's clocks, where blocks are resized and moved like in a calendar app and every edit rewrites the clock line.

- **Tab:** `Tracker | Timeline | Stats`, a new `'timeline'` value of `DailyViewTab` (remembered by `lastDailyViewTab`). It follows the daily view's note (previous/next/Today), redraws on store changes and grows the running block on the existing per-minute tick.
- **One block per clock line**, never merged. A block is identified by task name + the clock's start timestamp at the time it was read (line indexes shift, like dismissed-issue keys). One edit rewrites exactly one line.
- **Axis:** the note's day 00:00–24:00, stretched to include any clock or bed time beyond it, at most one day either way (a mistyped date would otherwise stretch it over months; blocks are clipped to it). The tab content scrolls under the note navigation and the tabs, which stay in place (all tabs, decided while building); on open each note is fitted to its day as the Fit button does, without saving that zoom (setting `timelineFitOnOpen`, on by default, added 2026-11-12); turned off, or with nothing to fit, it opens at the saved zoom scrolled to now (today's note), else the wake time, else the first clock. Wake and bed are drawn as lines with the span between them shaded.
- **Snapping:** step follows the zoom (15 / 5 / 1 min at fixed thresholds); a dragged edge lands on whole minutes. Magnet: within a few pixels a dragged edge sticks exactly to another block's edge, now, the wake line or the bed line. Alt disables all snapping (1-min moves). Untouched edges keep their seconds; a move keeps the duration to the second. A block never shrinks below one snap step (no zero-length clocks).
- **Running clocks:** the start edge is draggable, never past now, and the clock keeps running. Moving the block or dragging its end finishes it (changed 2026-11-12, was start only): it counts as ending now, a move keeps the duration so far, and the end lands where dropped; anything that would end at now or later leaves it running as it was. On a past note "now" is the end of the axis, so a clock left running there can be finished by pulling its end back onto the day. Styled as running (dashed/pulsing bottom edge).
- **Same-task overlap on drop is allowed:** both blocks get a warning outline and the existing overlap issue (with its consolidation fix) reports it. Cross-task overlap is normal and shares the width.
- **Layout (pure, in core):** overlap clusters (touching is not overlap), blocks sorted by start then longest first, greedy leftmost free column, each block expands right over columns free for its whole span. While dragging, the block floats as a ghost and the others stay put; the layout reflows on drop.
- **Write path:** on pointer up only, working from the drag-start snapshot. Re-read, find the clock by identity, rewrite that one line compare-and-swap (retry on change); if the clock is gone, notify "The clock changed elsewhere, nothing was written." and redraw.
- **Undo:** every drop saves at once and shows a notice (`Deep work 09:00–10:30 → 09:15–10:30`) with an Undo button, which writes the previous line back through the same path (found by its new identity). Covers the latest edit only.
- **Zoom:** pinch / Ctrl-or-Cmd + wheel anchored on the time under the pointer, plus a toolbar with −, + and Fit (fit wake→bed, else first→last clock; a bed time still ahead of now fits wake→last clock instead, now while one runs or when none is logged, changed 2026-11-12). Continuous from ~30 to ~600 px per hour. Saved as `timelineZoom` in settings; scroll position is not saved.
- **Block content:** tag emojis + name, then `09:15–10:30 · 1h 15m`, dropping duration then range as the block shrinks (color only when tiny); full text in a hover tooltip. Color: `taskColors[name]`, else the theme accent (`--interactive-accent`), not the stats tab's rank cycle: ranks follow time worked, so a block changed color while its clock was dragged (changed 2026-11-11 after trying it); tinted fill with a solid left border.
- **Click** (no movement past a few pixels; a tap on touch, a right-click, Enter or Space) opens the block menu (changed 2026-11-12, was a jump to the line): Go to clock line; Remove end time, the clock running again, offered on the task's latest clock only and while none of its clocks runs (an earlier clock running to now would cover the later ones); Delete clock line, keeping the task line. Both edits offer Undo; undoing a delete puts the clock back in time order among the task's clocks.

## Decisions (2026-11-18): timeline on touch, Duplicate as…

- **Pinch to zoom:** two fingers on the timeline zoom it through the same state as the toolbar (`setZoom`, clamped to `ZOOM_MIN`–`ZOOM_MAX`, saved to `timelineZoom`), anchored on the point between the fingers, as the trackpad pinch is on the pointer. The zoom follows the change in finger spread since they landed, applied once per animation frame: each step sets the scroll from the layout the previous one left, so two in one frame would anchor off target. The second finger cancels whatever the first began (a pending long press, a drag, a drawn clock) and clears the touch selection; no new press starts until the fingers lift. The canvas is `touch-action: pan-y` so the browser neither zooms the page nor takes the pinch, while one finger still scrolls. A pinch that starts after a one-finger scroll is under way cannot be taken from the browser (its touch moves are no longer cancelable): both fingers should land together.
- **⋯ button on blocks:** opens the block menu (the same `clockActions` menu as a click, a right-click or Enter), under the button. Top right corner, above the start handle. Shown on blocks at least 24 px tall (the 18 px round button and its 3 px inset); a shorter block has no room for it, and a tap or click on it opens the same menu. With a mouse it shows while pointing at (or focusing) the block; on touch screens (`hover: none`) it always shows, with a finger-sized hit area around it on mobile. Out of the tab order: the block itself opens the menu with Enter.
- **Duplicate as…:** a block menu action on finished clocks only (a running clock has no end to copy, and a running copy would make a second task run). It opens the draw picker (note tasks, vault tasks, create) without the clock's own task, whose copy would count the same time twice; since the picker never offers a vault or create twin of a note task, the source cannot be picked. The copy gets the same start and end, goes among the target's clocks in time order, and the task line is added when missing (`addClock`). Notice `➕ Duplicated "A" 09:00–09:30 as "B"` with Undo, which removes the copy and the task line it added, like undoing a drawn clock.

## Decisions (2026-11-18): overlap in the stats

Grilled on 2026-11-18; mockups and the reasoning behind each choice are on the design page ([Overlap, Goals, Progression](https://claude.ai/artifact/HzFaQChLbyyWJjEXHVsWJ2)).

- **One model for every number:** the range is cut into minutes, each recording the set of tasks active in it. A row's time, its overlap, its partners and the covered total all come from it. Two overlapping clocks of the same task count once (they count twice today). Computed by a sweep over clock start and end points, never minute arrays.
- **Covered is the headline:** the summary shows `Covered 8h · +1h concurrent`; the table footer reconciles rows, minus concurrent time, equals covered. Concurrency is always counted between tasks, after the block's filter, whatever the grouping (it describes the day, like Unlogged).
- **Share is a share of covered time** in every grouping. Shares may add up to more than 100% (concurrent tasks; multi-tag tasks in tag mode); the column header's tooltip says so. Split credit (`share: split`) is Later.
- **Overlap is for tasks only:** in task mode each row gets an Overlap % (minutes shared with another task ÷ the row's time), with a tooltip listing the partners (`with **Email** · 30m`; three-way overlaps appear under each partner; partners outside `top: N` show as Other). Tag and filter modes have no Overlap column. Overlapping tags were dropped.
- **Chart:** segments keep their full height, the shared part of each is hatched at its top (task mode only), and a tick across each bar marks covered time (every mode). No targets on this chart.
- No block option: the Overlap column and the hatching appear only when some task overlapped.
- **Restyled tables:** the block's tables (`KeyValueTable`) get a swatch per row matching its chart color, right-aligned tabular numbers, small muted headers, horizontal rules only, a muted footer, and a dotted underline on cells with a tooltip, all from Obsidian's CSS variables. Tooltip style: task names bold, `·` between a label and its amount.
- The plugin is unpublished, so the changed totals need no migration or announcement.

## Decisions (2026-11-18): progression

- **Two baselines:** previous (the period of the same length right before) and usual (the average of the N previous periods that have data). Block options `compare: both | previous | usual | none` and `compareWith: 4`; the default is `both` for every range, year ranges included. Custom spans and rolling windows compare with the same number of days before. `all` shows "Nothing to compare all with", a first period "No earlier data".
- **A period still running compares like for like** (confirmed 2026-11-19): this week on a Wednesday is compared with Monday to Wednesday of earlier weeks, this month on the 19th with the 1st to the 19th, so a fresh period never shows a large ▼ against full ones.
- **Comparisons load after the main stats are drawn**, with a "Comparing…" placeholder.
- **One Trend column** with the delta against usual (`▲ 3h 20m · +18%`); its tooltip gives this period, last period and usual, each with its delta. The summary shows `Covered 31h · ▲ 4h 10m vs usual`, `Start of day 07:10 · 18 min earlier`.
- **Deltas are neutral** (muted, no color) unless a goal states a direction: an "at least" time goal makes ▲ green, an "at most" one makes ▼ green; if the direction changed within the range, the latest goal wins. No separate "less is better" flag.
- **What gets a delta:** covered time, each row's time, each goal's achieved value and days met, start and end of day (as a time shift), off time, unlogged. Not Share % or Overlap %. No chart change.

## Decisions (2026-11-18): goals

- **Syntax:** goal lines under the task, like clock lines, so names, rename and tags are untouched; the clock syntax stays as it is. `[goal::<metric> <achieved>/<target> <unit>]`: one reserved key, `goal`; the metric is the text before the first number or `/`, or before a colon when present (required when the name contains a digit, `[goal::5k pace: 5.2/5 min/km]`); achieved and target are optional numbers (`.` or `,` decimal, no thousands separator); a target starting with `<` means at most, the default is at least; the unit is free text, kept as written, never converted. A time goal has no metric name and a duration with `h` or `m` (`[goal::1h30m]`, `[goal::<30m]`); its achieved value comes from the clocks and is never written. A bare number is an issue ("Add h or m, or a metric name"); the plugin writes `1h30m`; prompts still take a bare `90` as minutes. Other `[field::…]` lines under a task are left alone. Dataview compatibility is not a goal.
- **Goal lines come first**, right under the task line and before its clocks, in the order added. Clock re-sorting only reorders clock lines; a hand-written goal line after the clocks is read normally and moved up on the next plugin write to that task. Every `TaskNote` edit keeps them, with goal lines in the fixtures of every edit's tests.
- **Carry-over like tags:** a task line the plugin inserts gets its most recent occurrence's goals, targets only. Lines already in a note are never rewritten; goals from a note template win.
- **Suggested goals:** in the Goals tab, for every task in the note, the index offers the goals of its most recent day with goals that the note lacks (targets only) as suggested cards, and the same for `tag_goals`. Nothing is written until "Add to today"; ✕ dismisses a card for that day (plugin data, pruned after a week). Changed 2026-11-22: a toolbar labelled "Suggestions:" with text-only buttons with Accept all, Reject all and Reset (brings back every suggestion rejected for that day), shown whenever the day has suggestions offered or rejected, an unavailable action disabled rather than hidden; each button has a command and its tooltip says what it does, then teaches the shortcut. The Add goal card comes first, above every goal and suggestion. This covers notes made by a template or by hand.
- **Tag goals:** a configurable `tag_goals` frontmatter list (`"#work 6h"`, `"#leisure <2h"`), written through the same frontmatter text edit as `day_start` (Undo, Change). Time only in v1, measured as the covered time of the tasks carrying the tag. Copied from the most recent note that has it on the plugin's first write to a new note.
- **Per-metric settings**, keyed by metric name: color, emoji, aggregation rule `sum | average | last | min | max` (default sum; units containing `/` default to average). Time goals use ⏱. A task rename touches none of it; renaming a metric is Later. The settings list every metric of any note plus the ones with settings; a metric with settings that no goal line uses any more is flagged, with a button to forget its settings (settled 2026-11-22).
- **Goals tab** between Tracker and Timeline (`Tracker | Goals | Timeline`, a new `DailyViewTab`), following the daily view's note. A grid of cards with rings (layout B; a form, a status list, a week grid and four bar variants were rejected): one card per goal with the ring in the goal's color, round − / + on either side of the ring stepping achieved by 1 (or by the metric's precision), achieved and target inputs that size to their content (CSS `field-sizing: content` if Obsidian's Electron supports it, else a `size` attribute), time goals' achieved in a dashed read-only field without steppers, a ⋯ menu (Delete goal with Undo, Edit unit; Color and emoji and Hide from tracker later), suggested cards, and a dashed "Add goal" card (task or tag picker, metric picker with New metric, target and unit). Cards are grouped by task when there are many; done cards keep their place. Changed 2026-11-22: cards are always grouped under their task's name, whatever their number, and show only their metric.
- **Done state:** the ring closes in the goal's own color, the card gets a green tint and halo, no text label. A badge on the top-left corner, chosen in settings ("Done badge": None, Tick, Gold star, Rosette, Rubber stamp, Trophy, Streak flame), stamps in once when the target is reached while the tab is open (skipped with reduced motion). Rubber stamp texts come from a "Stamp texts" setting, one per line, one picked at random per card and kept for the day. Streak flame shows the days in a row the goal was met. Settled 2026-11-22: a day without the task or the goal ends the streak, unless that goal's own "Skip days without it in streaks" (its ⋯ menu, plugin data keyed by task and metric, migrated on rename and merge) is on. An "at most" goal is done at the end of the day if it stayed under the limit, and red as soon as it goes over.
- **Tracker rows:** one thin bar per goal under the row, in the goal's color with its emoji at the end; hovering shows `🏃 distance · 8 / 10 km · 80%`, clicking edits that goal with achieved focused. Changed 2026-11-22: the bars span the whole row, under the checkbox too, and clicking a metric goal's bar opens the Record goal result prompt for it (a time goal's bar, with no result to type, and the folded "+1" still open the Goals tab). At most 3 bars, the rest fold into "+1". No new row button; rows without goals are unchanged.
- **Commands:** Record goal result… (task → metric → number) and Set goal… (task → metric or new → target, unit if new). Accept all goal suggestions, Reject all goal suggestions and Reset rejected goal suggestions act on the command target's day (added 2026-11-22).
- **End day:** lists targets still missing a result ("No result for: Run · distance"), never blocks. Unclocked tasks with goal lines are never removed silently: End day and Complete journal list them apart under "Has goals", with their goals and a checkbox off by default, kept unless ticked; its note adds "You might want to keep them around for your statistics." (2026-11-22). Changed 2026-11-22: the missing-result list is a warning in End day's confirmation ("No results entered for the following goals:" and a bullet per goal), which now also opens when that list is the only thing to say, instead of a line of the final notice.
- **Rename and merge:** a metric on one side moves over; the same metric on both sides combines with its aggregation rule; mismatched units keep both lines (issue flag); two "at least" time goals add up, otherwise the surviving line's wins. The merge preview says "3 goals will be combined on 2 days".
- **Settled 2026-11-19:** merging the same metric with targets in opposite directions ("at least" and "at most") keeps the surviving line's target. The `tag_goals` property name is fixed, like `day_start`; no setting. End day opens its confirmation whenever an unclocked task has goals, even when nothing else would be deleted.
- **Issues** (task manager warning column): malformed goal lines, a bare number as a time goal, unit drift for a metric.
- **Stats:** a `goals` metric renders a Goals table (Goal left-aligned, other columns centered): achieved / target combined with the metric's rule over the days that had a target, %, days met, and a streak (one dot per day: met, missed, no goal; a weekly summary on year ranges). Time-goal rows of the main table show `22h 00m · ⏱ 96%` with a tooltip. Goal deltas join from Phase 13, colored by direction.
